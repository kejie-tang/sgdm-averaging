# Statements for the INFORMS submission system

These are ready-to-paste statements for the "Code & Data Disclosure" and
"Ethical Statements -> Reproducibility" sections, and for the manuscript's
Data/Code Availability note.

> **Note.** Operations Research uses *soft double-anonymous* review: reviewers
> do not see author names, but the Area/Associate Editors do. The repository

> the hosting account itself is the authors' personal GitHub account. If a

## Code and Data Disclosure

> All numerical results in the paper are produced by the code in the
> accompanying repository. The simulation experiments (quadratic loss,
> logistic loss, and the sensitivity / asymptotic-normality studies) use only
> synthetic data that are generated in-code from the seeds and parameter
> values described in Section 6 of the paper; no external data files are
> required. The real-data experiment uses the public MNIST dataset
> (LeCun et al.), which is freely available at
> http://yann.lecun.com/exdb/mnist/ and is not redistributed by the authors.
>
> Repository: https://github.com/kejie-tang/sgdm-averaging
> (also provided as a supplementary archive `code_release.zip`).

## Data Availability Statement

> The datasets analysed during the current study are either generated by the
> code provided (synthetic simulations) or are publicly available (MNIST,
> http://yann.lecun.com/exdb/mnist/). No new datasets were created and no data
> files are distributed with the code; the MNIST data can be obtained from the
> public source above or fetched automatically by the provided script
> (`python src/mnist/mnist_experiment.py --download`).

## Code Availability Statement

> The code reproducing all figures and tables is available in the repository
> https://github.com/kejie-tang/sgdm-averaging. A frozen copy is included as
> supplementary material.

## Reproducibility statement

> Every experiment is fully reproducible from the provided code. All random
> number generators are seeded per replication, and SGD and SGDM share the
> same pre-sampled mini-batch sequence within each replication. The mapping
> from each figure in the paper to the script that generates it, together with
> the exact parameter values, is given in `README.md` (Section 4 and the
> Figure-to-code table in Section 5).

## Suggested repository layout for the journal (per OR journal instructions)

The INFORMS guidance (https://orjournal.github.io/InstructionsForAuthors.html)
recommends organizing code so that a reader can reproduce each reported
result. This repository follows that recommendation:

* a top-level `README.md` with environment, hardware/software, data, and
  per-figure run commands;
* a `LICENSE` (MIT) and `AUTHORS` file, as required by the INFORMS guidelines;
* a `src/` directory split by experiment, one script per figure group;
* a shared `src/sgdm_core.py` so all experiments use identical conventions;
* a `scripts/` directory with `run_all.sh` for one-command reproduction;
* a `data/` directory that **documents where the public MNIST files come from**
  (no data files are committed); and
* a `docs/` directory with these statements; and
* a `results/` directory that holds the paper's figures, the raw numeric
  arrays, and the authors' run logs.

### Anonymous GitHub mirror (optional, fully anonymous link)

<https://anonymous.4open.science/> builds a read-only, term-redacted mirror of
the repository above and hands back a random slug such as
`https://anonymous.4open.science/r/840c8c57-...`. Nothing about the account is
exposed, and the mirror can be set to expire after the review round. If you use
this, give reviewers the slug rather than the `github.com` URL.

### Supplementary archive (no URL at all)

Upload `code_release.zip` through the journal's own submission system as
supplementary material. This never exposes a URL, but reviewers cannot browse
it as conveniently as a repository.

## Checklist before pushing

Re-check after any edit that touches the files or the history. Substitute your
own identifying terms into `TERMS` first (author surnames, affiliations,
institution abbreviations, e-mail domains):

```bash
TERMS="surname1|surname2|university|department|institute-abbrev"

# 1. no names / affiliations / e-mails in the files
grep -rniE "$TERMS" --include="*.md" --include="*.py" --include="*.sh" .

# 2. no names in the git history
git log --all --format="%an <%ae> %s" | grep -iE "$TERMS"

# 3. no local absolute paths (would leak a user name)
grep -rnE "/Users/|/home/|[A-Z]:\\\\\\\\Users" --include="*.py" --include="*.sh" .
```

If (1) or (2) match, re-anonymize before pushing. History is rewritten with

```bash
git filter-branch -f --env-filter '
export GIT_AUTHOR_NAME="Anonymous Authors"
export GIT_AUTHOR_EMAIL="anonymous@example.com"
export GIT_COMMITTER_NAME="Anonymous Authors"
export GIT_COMMITTER_EMAIL="anonymous@example.com"
' -- --all
rm -rf .git/refs/original
git reflog expire --expire=now --all && git gc --prune=now
```

(this has already been applied: every commit is authored by "Anonymous Authors
<anonymous@example.com>").

## Pushing

The remote is already configured; to re-push:

```bash
cd code_release
git push
```

To start over from scratch:

```bash
git remote add origin git@github.com:kejie-tang/sgdm-averaging.git
git push -u origin main
```

## After acceptance — restoring authorship

Create a final, non-anonymous release:

1. Restore the author list in `AUTHORS`, `README.md` and `LICENSE`.
2. Mint a **DOI** for the archival copy (e.g. via Zenodo) and cite it in the
   manuscript's Code Availability statement.
